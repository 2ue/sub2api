## Why

当前项目已经具备完整的用户登录态、用户/分组/使用记录数据和现成的统计查询能力，但没有一个独立的消费报表系统可以在不改动现有主系统的情况下直接查询某个用户在指定时间段内按分组和平台拆分的消费。

这次变更要把报表能力拆成一个独立服务和独立页面，复用现有 JWT 登录态和数据库数据源，但不把页面和接口挂进当前系统的导航与业务流。

## What Changes

- 新增一个独立的报表服务二进制，提供自己的页面和 API，不接入当前系统的主导航和主业务路由。
- 新增一次性报表查询能力：按时间段查询当前用户或指定用户的消费，并返回分组维度和平台维度的汇总。
- 新增服务端 JWT 校验和用户解析逻辑，复用当前登录态，不要求用户在报表系统里二次登录。
- 新增用户搜索接口，仅供具备权限的调用者选择其他用户时使用。
- 新增安全边界：浏览器不持有任何管理密钥，跨用户查询和权限判断都在服务端完成。
- 新增针对报表查询、权限边界和页面加载行为的测试。

## Capabilities

### New Capabilities
- `standalone-usage-report`: 独立消费报表服务、报表页面、bootstrap / user search / summary API、以及按分组和平台拆分的消费查询能力。

### Modified Capabilities

- None

## Impact

- 后端新增 `backend/cmd/report` 独立入口，以及 `backend/internal/usagereport/` 相关实现。
- 新服务复用现有数据库、JWT 密钥、用户仓储、分组仓储和使用记录表。
- 前端不修改当前主系统导航；报表页面由新服务独立提供。
- 不新增数据库迁移，不修改当前主系统的路由、认证流程或使用记录写入逻辑。
