## Context

当前系统的登录态保存在浏览器 `localStorage` 中，axios 请求拦截器会自动把 `auth_token` 作为 `Authorization: Bearer` 附加到请求里。只要报表服务和当前登录入口处在同一个 origin，浏览器就可以无感复用登录态。

现有仓库已经有可复用的能力：

- 用户仓储支持按 ID、邮箱和模糊搜索查用户。
- 分组表里已经有平台字段。
- `usage_logs` 已经能够按用户、分组、账户和平台聚合。
- 现有统计查询已经使用 `actual_cost > 0` 过滤掉占位记录，并且已经有有效平台表达式可复用。

报表系统的目标是把这些能力拼成一个独立页面，而不是把逻辑塞回当前主系统的 `/usage` 或 `/admin/usage` 页面里。

## Goals / Non-Goals

**Goals:**

- 以独立服务的形式提供报表页面和 API。
- 复用现有登录态，避免报表系统二次登录。
- 允许当前用户查询自己的消费，允许具备权限的调用者查询其他用户。
- 一次请求返回总览、分组拆分和平台拆分结果。
- 使用浏览器传入的时区解释日期区间，避免“今天”在不同时区下含义不一致。
- 浏览器不接触任何管理密钥或服务端凭据。

**Non-Goals:**

- 不修改当前主系统的路由、菜单和用户用量页面。
- 不新增定时推送、自动刷新或后台轮询查询。
- 不做图表、导出、订阅或报表调度。
- 不引入新的数据库表或迁移。
- 不在浏览器里保存任何报表专用密钥。

## Decisions

### 1. 使用独立 `report` 二进制，而不是接入当前主服务

报表页面和 API 作为一个独立服务运行，自己的路由、静态页面和认证中间件都放在 `backend/cmd/report` 下面。

原因是用户明确要求“独立系统，不改当前系统”。把报表功能挂进现有主服务会让它继续依赖当前系统的路由和导航，边界不够清晰。

### 2. 认证仍然沿用当前 JWT 规则，并在服务端完成用户解析

报表服务使用当前 JWT secret 验证 bearer token，随后通过用户仓储重新加载用户并检查状态、token version 和会话绑定。

替代方案是浏览器持有一个额外的管理密钥或报表专用 token。这个方案会把高权限凭据暴露给前端，违反安全边界，也不符合“浏览器不接触 admin key”的要求。

### 3. 其他用户查询只对管理员开放

报表接口支持自查询和他人查询，但跨用户查询只允许管理员身份使用。

替代方案是允许任何登录用户任意查询其他用户。这个方案在安全上不可接受，因为报表系统本身会拿到全量消费明细。

### 4. 一次汇总请求同时返回分组和平台拆分

后端针对同一用户、同一时间范围执行两条受限 SQL 聚合：一条按分组聚合，一条按有效平台聚合，然后在同一个响应里返回。

替代方案是前端轮询按组逐个查询。这个方案会放大请求次数、失败点和前端状态复杂度，也更容易漏掉零值过滤与排序规则。

### 5. 页面以轻量静态页交付，而不是再建一个完整 SPA

报表服务直接内嵌一个静态 HTML / CSS / JS 页面，使用浏览器 `fetch` 调 API。

替代方案是再开一个多页 Vue/Vite 构建入口。那个方案能复用现有前端栈，但会把报表功能重新绑回当前前端工程，和“独立系统”的目标冲突更大。

## Risks / Trade-offs

- [Same-origin dependency] 报表页要无感复用当前登录态，部署时必须保证它和当前登录入口在同一 origin 下。→ 通过反向代理或同域路径挂载来部署报表服务。
- [Cross-user access width] 只允许管理员跨用户查询会比“所有人都能查任意用户”更收敛。→ 服务端返回明确的 403 和权限标记，避免前端误导。
- [Long-range query cost] 长时间区间可能触发较大的聚合扫描。→ 限定只做手动查询，不做自动刷新，并且只返回 `actual_cost > 0` 的结果。
- [Timezone ambiguity] 如果不传时区，同一天的边界会因浏览器和服务端不同而偏移。→ 请求里显式带上时区，服务端按它解释日期。
- [Static page maintenance] 轻量静态页的复用性不如完整 SPA。→ 这个报表系统只做消费查询，不承担复杂交互。

## Migration Plan

1. 新增独立报表服务和静态页面，不修改当前主系统的路由。
2. 在同域路径或同 origin 反向代理下发布报表服务，保证可以读取现有登录态。
3. 验证 bootstrap、用户搜索和汇总查询都能在当前账号体系下工作。
4. 回滚时只需撤掉报表服务的代理入口或停掉报表二进制，不影响当前主系统。
